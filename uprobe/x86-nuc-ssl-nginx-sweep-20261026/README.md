# x86 NUC：ssl-nginx 7 档 payload 扫测（2026-10-26 19:25–19:58）

Jetson `ssl-nginx-sweep-bca2ebce-20261024` 的做法：官方 `benchmark/ssl-nginx/draw_figture.py` 的 7 个大小（16 B–256 KB），
每档 5 次，不追踪 / kernel / 官方 177a1dc / a7d54d7e 四组轮换，每档先做 3 秒事件审计。
镜像、产物、sslsniff、`run_fair.py`、绑核和频率与 `../x86-nuc-ssl-nginx-20261026`（2 × 10 那轮）完全相同：
nginx 在 P 核 CPU 2、sslsniff 在 P 核 CPU 4（3.5 GHz），wrk 在 E 核 8–9（2.5 GHz），turbo 开、min = max、C6+ 禁用。
`run-sweep.sh` → `summary-sweep.md`、`absolute_performance.png`、`relative_to_kernel.png`、`overhead_trend.png`（Jetson 的 `plot_sweep.py`，只把开发分支名换成 a7d54d7e）。

- 频率：nginx 所在 CPU 2 忙碌 > 90% 的 1,331 个采样全部在 3.5 GHz ± 3% 内；测前测后忙碌检查通过；测完恢复原设置；容器已删。
- 原始 sslsniff 输出（16 GB）10/26 已从 NUC 删除（用户同意），仓库里只留首尾各 20 行；每档事件数在 `audit-*.json`。

**官方从 1 KB 起就丢事件**（4 KB 时只收到 45%），所以 1 KB 及以上官方的吞吐不是公平对比（它少做了一半以上的输出工作）；
Jetson 上官方只在大 payload 时丢（256 KB 收到 9.46/18）。原因同开发分支 `db3d475f` 修的 perf 缓冲区静默丢事件。

## 观察

1. a7d54d7e 每档都比 kernel 快，领先从 16 B 的 +50% 收窄到 256 KB 的 +26%，与 Jetson 的趋势相同（+17% → +12%），幅度约是 Jetson 的 2–3 倍。
2. 每个 SSL 事件 kernel 约 4 µs（Jetson 13 µs），基本不随大小变：成本是 uprobe 陷入和 helper，不是数据。
   a7d54d7e 从 1.0 µs 涨到 1.3 µs（Jetson 6.4 → 8.5 µs），随大小增加的部分是复制（sslsniff 每事件最多复制 8 KB）。
3. 领先收窄主要是分母变大：大 payload 时每请求的 TLS 工作和两边都要付的复制占比上升（kernel 相对不追踪的损失也从 44% 降到 32%）。
4. 2 × 10 那轮的 16 B（+48.0%）和 256 KB（+27.9%）与这里（+50.2%、+26.4%）一致。
