The reason for this issue is likely as follows: the hardcoded uprobe target function name in `launchlate` (a C++ mangled name, which encodes "function name + parameter type information" into a unique string to help the linker distinguish overloads/template instances) does not match the actual symbol name present in your `vec_add`/CUDA runtime on your machine. (Changes in CUDA versions/headers/compilation methods can lead to variations in symbol mangling. Our primary testing machines currently support CUDA 12.6, which might not be consistent with your CUDA 12.0).

If you encounter similar problems next time, you can do the following:

**Step 1:** First, confirm which `cudaLaunchKernel`-related symbols are actually present in `vec_add` (this is the GPU function you want to hook).
`readelf -Ws ./vec_add | rg "_Z16cudaLaunchKernel|cudaLaunchKernel"`

**Step 2:** Select a `_Z16cudaLaunchKernel...` symbol whose "address is not 0 and is not UND" (undefined), for example, `_Z16cudaLaunchKernelIcE9cudaErrorPKT_4dim3S4_PPvmP11CUstream_st`.

**Step 3:**
**Method A:** `./launchlate "./vec_add:_Z16cudaLaunchKernelIcE9cudaErrorPKT_4dim3S4_PPvmP11CUstream_st"`
**Or**
**Method B:** Change `const char *uprobe_spec = "./vec_add:_Z16cudaLaunchKernelIcE9cudaErrorPT_4dim3S3_PPvmP11CUstream_st";` to `const char *uprobe_spec = "./vec_add:_Z16cudaLaunchKernelIcE9cudaErrorPKT_4dim3S4_PPvmP11CUstream_st";`
