## Description

Fix CUDA `__constant__` / `__device__` globals losing their value after a GPU probe is attached.

When a CUDA kernel that reads a `__constant__` global (e.g. `__constant__ int d_N;` populated via `cudaMemcpyToSymbol`) is probed, the kernel runs in the patched module, but the agent's `mirror_cuda_memcpy_to_symbol` fallback cannot resolve the host symbol of the constant. Two gaps caused this:

1. `read_function_symbols_impl` in `nv_elf_introspect.cpp` only collected `STT_FUNC` symbols and skipped `STT_OBJECT` data objects, so CUDA `__constant__` / `__device__` globals were never indexed for host-address → symbol resolution.
2. Even when the symbol is indexed, the host-side name is Itanium mangled (e.g. `_ZL3d_N`) while the device module exports the plain name (e.g. `d_N`); the mirror fallback only tried the raw name.

As a result the patched module kept the default `0` for such constants, and any kernel guarded by `if (idx < d_N)` silently skipped its work (observed as `C[1]` turning from `3` to `0`).

Changes:
- `attach/nv_attach_impl/nv_elf_introspect.cpp`: collect `STT_FUNC`, `STT_OBJECT`, and `STT_NOTYPE` symbols.
- `attach/nv_attach_impl/nv_attach_impl.cpp`: in the `mirror_cuda_memcpy_to_symbol` fallback, look up the global by both the raw host symbol name and its demangled name (via `boost::core::demangle`).

Fixes # (issue)
