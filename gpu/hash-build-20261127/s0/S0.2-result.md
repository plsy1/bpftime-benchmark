# S0.2 result: the device hash map's functions called for real (2026-11-27)

Rules: `../S0-RULES.md` (S0.2, with the validity rule added before the timed runs). Generator:
`make_s02.py`; analysis: `analyze_s02.py`; outputs in `s02/`.

## What was compiled

The `lat` tool's lookup of its sum map (1531) in llama.cpp's probed `mul_mat_vec_q` (Q4_K, one
column; the only probed kernel), from the by-value build's dump (tvf-7d02d677, `81ea6349...ptx`),
rewritten by hand into what S6 will emit for a constant-fd lookup of a 1533 map:
- key, home slot, one `ld.relaxed.gpu.global.b64` of the header; live K: the sharded value address;
  empty: NULL, no call; otherwise a call of `__bpftime_devhash_lookup`; one `mov` at the join;
- the program's NULL branch: the value 1 on the program's stack and a call of
  `__bpftime_devhash_insert(base, key, &one, BPF_NOEXIST, 260, 256)`;
- the shipped devhash text (`devhash_ptx.h` of 309a9e8c6) at the start of the module body (D1);
- the block: a module-scope array (260 entries, 256 shards, 555,264 bytes), empty at load.

No probed kernel loses warps per SM: the rule's report-to-user case does not arise.

**SASS forms** (`dh_route.subs.txt`):
- inline path (in the probe): the header load is `LDG.E.64.STRONG.GPU`, with no `CCTL` or `MEMBAR`;
- `__bpftime_devhash_lookup` (149 instructions): `LDG.E.64.STRONG.GPU` in the walk,
  `RED.E.ADD.64.STRONG.GPU` for the full-walk counter;
- `__bpftime_devhash_insert` (347 + 85 instructions; ptxas splits a loop exit into an internal
  `CALL.REL`): the value read `LD.E.64` (generic); header loads `LDG.E.64.STRONG.GPU`, and
  `LDG.E.STRONG.GPU` (32-bit) where only the state is needed; `ld.acquire` = `LDG.E.64.STRONG.GPU` +
  `CCTL.IVALL`; the claim `ATOMG.E.CAS.64.STRONG.GPU`; the reservation `MEMBAR.ALL.GPU`, `ERRBAR`,
  `ATOMG.E.ADD.64.STRONG.GPU`, `CCTL.IVALL`; each `st.release` = `MEMBAR.ALL.GPU`, `ERRBAR`,
  `STG.E.64.STRONG.GPU`; counters `RED.E.ADD.64.STRONG.GPU`; `NANOSLEEP` in the waits.

**Mutation** (`dh_after`: the devhash text appended after the probes): ptxas refuses the module,
"Call to '__bpftime_devhash_lookup' requires call prototype" (and the same for the insert).

**Routed 1533 form minus 1531 form: +0.0381 and +0.0358 ns per thread (spread 0.0023).** This is S8's
expected cost. Round one's C2 measured +0.034 (lat) for an inline hit with no calls in the
module; with the fallback and insert calls present the steady state (every call an inline hit
after the first touches) costs about the same.

**Validity** (all hold in passes c and d): every override item logged "PTX override"; the 1531 sum
is 15,711,207,424 (= WANT) for `hd_t0` and `dh_check`, and 0 for `dh_route`; bucket 194 is 0.
So every probe call in `dh_check` found its key inline or through the call, or inserted (0) or lost
the insert race (-17).

**Two earlier passes (a, b) were invalid and are not used.** The GPU lock was taken with `flock`
without `-o`, so the harness inherited the lock's descriptor; the loader's maps got fds 5 and 15
instead of 4 and 14, the generated PTX (which holds the fd) changed, its sha no longer matched the
override's file name, and every item ran today's 1531 code. The validity check caught it (no "PTX
override" line; `dh_route`'s 1531 sum = WANT). As an A/A check those passes agree with each other
to 0.0005 ns per thread (`s02/analysis-invalid-fd-leak.txt`). Passes c and d ran with `flock -o`.

Note for S8: the frozen builds under `proto/builds/` load their PTX pass libraries from the
worktree's `build-cuda` (the path is compiled in): a pass change there (S6) also changes what a
"frozen" build emits.
